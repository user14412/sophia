# Agent Podcast Project Cleanup Spec

## 背景
当前项目是一个面向哲学播客/视频生成的 Agent 工作流原型，已经具备 LangGraph 状态图、RAG、双主持人脚本生成、TTS 配音、静态/生成式配图、FFmpeg/MoviePy 合成、SQLite checkpoint 等能力。项目适合用于 Agent 课程作业的工程实践与设计主题。

但当前代码仍处于实验堆叠状态：入口配置硬编码，运行一次成本高，调试必须穿过 LLM、RAG、TTS、图像和视频合成等重依赖；缺少前端和轻量调试模式；测试目录为空；依赖清单缺失；历史文档、运行产物、模型资产、样例数据和核心代码边界不清；部分旧管线存在异步/同步混用、JSON 解析不稳定、路径硬编码、日志和手工测试代码混杂等问题。

本阶段的目标不是继续扩展功能，而是先整理出一个稳定、可演示、可调试、可写入课程报告的工程基线。

## 目标
- 建立项目整理后的最小可运行基线，支持用固定样例低成本跑通核心 Agent 工作流。
- 降低调试成本，使内容生成、RAG、TTS、配图、视频合成可以按阶段单独验证，而不是每次从头全链路运行。
- 明确项目边界，把核心代码、实验代码、本地资产、生成物、课程作业文档分层管理。
- 保留已有工程亮点，例如 LangGraph 编排、checkpoint、RAG、异步并发、多角色对话生成，同时暴露其可观测状态。
- 为后续前端、报告撰写、功能改进留下稳定接口和清晰文档。

## 功能需求
- F1: 项目必须提供一个清晰的运行模式划分，至少区分完整运行、轻量演示、单阶段调试三类使用场景。
- F2: 项目必须允许用户在不改源码的情况下指定关键运行输入，包括参考章节、是否启用 RAG、是否启用真实 TTS、是否启用真实配图、是否执行视频合成、输出目录和会话标识。
- F3: 项目必须提供一个低成本演示路径，可以绕过或模拟外部重依赖，并产出可用于作业展示的脚本、字幕或伪产物摘要。
- F4: 项目必须支持按阶段恢复或跳过已经完成的阶段，避免每次调试都从头调用 LLM、RAG、TTS 和视频合成。
- F5: 项目必须整理并记录当前推荐主线流程，明确 v3 播客特化流程是课程作业优先展示路径，旧的通用视频流程作为兼容或后续整理对象。
- F6: 项目必须把配置、密钥、本地路径、外部服务地址和硬编码示例从业务逻辑中剥离出来，并提供示例配置说明。
- F7: 项目必须建立最小测试与验证体系，覆盖不依赖真实外部服务的纯逻辑、状态流转、配置解析、RAG 结果处理、脚本切分、SRT 时间轴和视频合成命令构造。
- F8: 项目必须提供面向课程作业的工程说明文档，说明系统目标、模块架构、运行方式、已知限制、AI 使用说明和可展示产物位置。
- F9: 项目必须整理仓库资产边界，避免模型权重、数据库、运行日志、临时输出和个人密钥被误认为核心源码或课程提交材料。
- F10: 项目必须统一错误处理和可观测输出，使 JSON 解析失败、外部服务不可用、文件缺失、依赖缺失、checkpoint 恢复等问题能给出明确诊断。
- F11: 项目必须保留当前已有的断点续传能力，并使用户能够理解如何新建会话、恢复会话和清理会话。
- F12: 项目必须为后续前端接入预留稳定的输入输出边界，但本阶段不要求实现前端。

## 非功能需求
- N1: 整理阶段应优先保证可重复运行和可验证性，不追求生成质量的最大化。
- N2: 轻量演示路径应尽量不依赖 GPU、本地 GPT-SoVITS 服务、DashScope 文生图、FFmpeg 硬件编码或真实大模型调用。
- N3: 完整运行路径可以继续依赖真实 API 和本地服务，但缺失依赖时必须快速失败并给出明确提示。
- N4: 配置和文档不得包含真实 API key、个人隐私路径或不可公开的密钥内容。
- N5: 测试应能在普通开发环境中运行，默认不触发昂贵网络请求、模型下载、TTS 推理或视频渲染。
- N6: 整理后的目录结构应支持课程报告复现：读者能理解哪些是源码、哪些是样例输入、哪些是生成输出、哪些是开发记录。
- N7: 变更应尽量保持现有主流程语义，不在本阶段重写 Agent 内容策略或提示词体系。
- N8: 所有新增说明文档应使用中文为主，必要的技术名词保留英文。

## 不做的事
- 不实现 Web 前端、桌面前端或可视化工作台。
- 不新增 BGM、表情包库、情感匹配配图、Neo4j、联网资料抓取或复杂知识图谱。
- 不重写全部提示词，不以提升播客内容质量为本阶段主要目标。
- 不训练、微调或替换 TTS/图像/LLM 模型。
- 不保证旧的 v2.1 通用视频管线在本阶段完整修复到生产可用；除非它影响主线整理。
- 不把本地大模型权重、语音数据集、Chroma 数据库或历史运行产物纳入课程提交核心材料。
- 不生成最终课程报告正文；本阶段只为报告准备工程基线和说明材料。

## 验收标准
- AC1: 用户可以阅读项目说明后明确知道推荐运行哪条主线流程、需要哪些配置、产物在哪里。
- AC2: 用户可以在不修改源码的情况下选择完整运行、轻量演示或单阶段调试。
- AC3: 用户可以用轻量演示路径完成一次端到端流程验证，并看到脚本、字幕或伪产物摘要等可观测输出。
- AC4: 用户可以单独验证内容生成前后的关键阶段，而无需每次真实调用 TTS、文生图和视频合成。
- AC5: 用户可以指定或复用会话标识，并理解如何恢复或清理 checkpoint。
- AC6: 当缺少 API key、本地 TTS 服务、参考文件、FFmpeg 或静态图片时，系统给出明确错误信息，而不是在深层调用中模糊失败。
- AC7: 不依赖外部服务的测试可以运行，并覆盖核心纯逻辑和状态流转。
- AC8: 仓库中课程作业相关文档、开发 spec 文档、源码、样例资料、生成物和本地资产边界清楚。
- AC9: 真实密钥和个人本地配置不会出现在新增文档或可提交文件中。
- AC10: 课程报告可引用的工程说明文档已经存在，并能支撑“工程实践与设计”选题叙述。
