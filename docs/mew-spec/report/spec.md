# Agent 课程大作业报告 Spec

## 背景

本次任务不是继续修改项目代码，而是在时间有限的情况下，基于现有 Sophia Agent Podcast 项目完成一份课程大作业报告。报告需要满足课程通知与模板要求：提交 PDF，排版参照《软件学报》，首页显式标注选题编号，注明姓名和学号，论文字数约 3500 字，并说明 AI 生成技术的使用情况。

作业选题截图给出 A-F 六类方向。本项目最适合归入 **E：工程实践与设计**，可聚焦“智能体工作流、知识系统、智能体设计模式与工程化原型”。报告不以源码提交为目标，而以系统设计、原型实现思路和案例产物分析为主。

现有项目材料包括：

- `作业相关/作业要求/通知.md`：提交格式、字数、AI 使用说明、截止时间和提交链接。
- `作业相关/作业要求/1.jpg`：选题建议，项目对应 E 类。
- `作业相关/报告模板/latex.tex` 与 `rjthesis.cls`：软件学报风格模板。
- `docs/dev-docs/二周目baseline重构/3.0播客内容生成管线设计.md`：v3.0 管线设计思想。
- `docs/product/播客产品设计.md`：教育播客产品定位与制作流程。
- `resources/outputs/ch01-demo/`：可用于报告展示的 topic、director、script、voice、image、video 等中间产物。

## 目标

- 完成一篇约 3500 字的课程报告，题目暂定为《面向教育播客生成的多阶段 Agent 工作流设计与原型实现》。
- 首页明确标注选题编号：**E：工程实践与设计**。
- 报告开头 100 字内说明本文与 Agent 新技术的关系。
- 使用软件学报风格结构：标题、作者信息、摘要、关键词、正文分节、图表、参考文献、AI 使用声明。
- 报告主线聚焦“多阶段 Agent 工作流如何把知识材料转化为教育播客脚本和媒体产物”，而不是项目近期调试 bug 的细枝末节。
- 利用已有项目文档和中间产物支撑论述，但不要求报告逐项对应当前代码的全部真实状态。

## 功能需求

- F1: 报告必须符合课程提交要求，包括 PDF 格式、软件学报风格、选题编号、姓名学号、约 3500 字、AI 使用说明。
- F2: 报告必须采用清晰的 Agent 技术主线，说明该项目如何体现大模型智能体、工作流编排、多阶段协作、知识增强或媒体生成。
- F3: 报告必须有完整论文结构，而不是项目 README 或流水账。
- F4: 报告应弱化近期工程整理中的端口、前端、环境变量、上传失败、manifest 等细小调试细节。
- F5: 报告应把项目描述为“面向教育播客生产的多阶段 Agent 原型系统/设计实践”，以避免过度承诺一个完全稳定的产品系统。
- F6: 报告应包含至少 2 个图表或表格设计，例如系统工作流图、阶段职责表、产物示例表。
- F7: 报告应包含一个案例分析段落，使用已有 `resources/outputs/ch01-demo/` 中的 topic、director、script 等产物说明系统输出形态。
- F8: 报告应包含局限性与未来工作，主动说明真实 LLM/TTS/视频生成链路成本高、稳定性依赖外部服务、评估仍可加强。
- F9: 报告应包含 AI 使用声明，说明报告整理、代码理解或文字润色中使用了 AI 辅助。
- F10: 报告应包含少量核心参考文献，采用顺序编码制标注；参考文献以 Agent、RAG、多智能体协作和 LangGraph/工作流编排为主，不堆砌无关工程依赖。

## 非功能需求

- N1: 文字风格应接近课程论文，避免口语化、抱怨式和开发日志式表达。
- N2: 论述应“可信但不自曝短板”：不写细碎 bug，不写调试混乱过程；但也避免编造大规模实验数据。
- N3: 结构优先服务快速完成，正文应便于后续直接扩写成完整论文。
- N4: 图表应能用文字、Mermaid、LaTeX 表格或截图等方式快速落地。
- N5: 若最终排版时间不足，优先保证正文质量、选题合规和 PDF 可提交。

## 不做的事

- 不继续重构项目代码。
- 不在报告中详细描述最近修复的端口占用、前端代理、上传 manifest 等小问题。
- 不把报告写成使用手册或 README。
- 不把旧 v1/v2.1 开发心路历程原样搬进正文，只作为设计动机素材。
- 不编造不存在的大规模用户实验或严格对照实验数据。
- 不要求提交源码，也不把源码结构作为评分重点。

## 推荐报告大纲

### 题目

面向教育播客生成的多阶段 Agent 工作流设计与原型实现

### 摘要

概述教育类播客生产的痛点：知识材料长、结构组织难、对谈脚本质量依赖人工编导、媒体生成链路复杂。提出一个多阶段 Agent 工作流，将输入章节依次转化为主题规划、编导大纲、双人对谈脚本、配音摘要、画面计划和视频产物。摘要最后点出本文属于选题 E：工程实践与设计。

### 关键词

大模型智能体；多智能体协作；工作流编排；教育播客；检索增强生成；媒体生成

### 0. 选题说明与 Agent 技术关系

在正文开头 100 字内明确写：本文选题编号为 E，围绕智能体工程实践与设计，讨论一个面向教育播客生成的多阶段 Agent 工作流原型。该系统将大模型智能体用于任务分解、角色化对话生成和媒体生产编排。

### 1. 引言

说明知识型视频/播客制作的人工成本，以及单次提示词生成长脚本容易出现结构失控、知识漂移和难以调试的问题。引出本文的核心思路：把“长文本一次生成”改造成“多阶段、可检查、可重跑的 Agent 工作流”。

### 2. 需求分析与设计目标

从教育播客角度提出系统需求：

- 面向零基础听众，内容需要从浅入深。
- 对谈脚本需要有提问、解释、追问、转场。
- 系统需要保留中间产物，便于人工检查和阶段调试。
- 媒体生成链路需要把文本、语音、图像和视频组织起来。

本节可引用产品设计文档中的“知识锚点、听众嘴替、幕后统筹”三类角色，把它们映射为 Agent 职责。

### 3. 系统总体架构

介绍三层结构：

- 知识层：参考章节、RAG 或静态资料，为内容生成提供依据。
- 内容层：Topic、Director、Agent Speechers，负责把知识材料变成对谈脚本。
- 视图层：Voice、Image、Editor，负责把脚本转成语音、画面和视频产物。

建议放图 1：`参考章节 -> Topic -> Director -> Agent Speechers -> Voice -> Image -> Editor -> 播客视频`。

### 4. 多阶段 Agent 工作流设计

重点写三个机制：

- Topic：把长章节拆成递进主题，体现 zero-to-hero 的教育逻辑。
- Director：把主题变成可执行的编导阶段，明确每段的意图、素材和转场。
- Agent Speechers：用双主持人角色生成对谈脚本，模拟苏格拉底式问答。

再补充上下文设计：

- System Prompt 固定角色和表达风格。
- Current Task 明确当前问题和下一步抛接。
- Memory 使用滑动窗口维持对话连贯。
- Knowledge Base 使用章节资料或检索结果减少幻觉。

### 5. 原型实现与案例分析

使用 `resources/outputs/ch01-demo/` 作为案例，不需要说它是最近调试产物。可写成“原型运行示例”：

- Topic 产物示例：系统将章节拆为“从自然追问到人的转向”“苏格拉底与可对话的智能体”等主题。
- Director 产物示例：为主题生成“问题导入”“Agent 协作解释”等阶段。
- Script 示例：双主持人围绕古希腊哲学与 Agent 协作展开对谈。
- Voice/Image/Editor：展示后续媒体阶段的产物接口和摘要。

建议放表 1：阶段、输入、输出、作用。

### 6. 工程化分析与讨论

分析该设计的工程价值：

- 可解释：每个阶段都有中间产物。
- 可调试：某阶段失败时可单独检查输入输出。
- 可扩展：可替换 LLM、TTS、图像生成或剪辑模块。
- 可加入人工审核：在 topic 或 director 后插入人工修改。

同时讨论限制：

- 真实链路依赖 API、TTS、FFmpeg 等外部服务。
- 内容质量仍依赖提示词和参考资料质量。
- 评价体系还不完善，后续可加入人工评分和自动指标。

### 7. AI 使用与伦理说明

说明系统本身使用大模型生成内容，因此需要区分参考知识、模型生成文本和人工审核结果。报告撰写过程中也使用 AI 辅助阅读代码、整理结构和润色文字，最终内容由作者确认。

### 8. 总结

总结本文贡献：提出并实践了一个面向教育播客生成的多阶段 Agent 工作流，将长文本生成拆解为可检查、可扩展的工程管线；该实践体现了 Agent 技术在知识内容生产中的应用价值。

采用顺序编码制，正文用 `[1]`、`[2]` 等编号标注，文末列出 4 条左右核心参考文献。优先保留：
